# V2.0 研究方案：固定查询下的词法、语义与混合检索

版本：planning-v1，2026-10-27。状态：**方案草案，尚未实现、建立新划分或运行实验**。本轮仅封存 V1.1 并提交此研究方案。方法接口、模型、数据队列和未来预算仍须在后续任务中落定；本文件不构成 GPU、模型下载、微调或推理授权。

## 1. 证据起点与研究问题

V1.1 dev 上 format_details Hit@10=0.90、Baseline=0.80；独立 100 图中变为 0.72 对 0.78，配对差 95% CI=[−0.17, 0.05]。六条附加格式合约失败全部计零，MRR@10 基本相同。开发集优势未在独立测试中稳定复现，不能宣称显著提升。[正式审计](v11_independent100_audit.md)

这些结果支持继续研究失败成本与检索过程，但**不能定位 BM25 就是失败原因，也不能推断换成 Dense 必然改善**。V2.0 首先控制查询生成：对同一张图片只生成并保存一次 Baseline 文本查询，让三种检索器处理完全相同的文本，避免同时改变 Prompt、格式校验和检索方法。

中心问题：在相同图像查询、候选库、相关性定义和完整失败分母下，语义匹配与词法匹配能否互补？这种互补是否足以改善 Hit@10，并抵偿编码、索引、查询延迟和存储成本？

待检验假设：

- H1：Hybrid 相比 BM25 可能覆盖词面不同但语义相近的相关描述，改善 Hit@10；也可能引入只在主题上相似的错误结果。
- H2：Dense 与 BM25 的优劣可能依赖实体/数字/可见文字、动作及同义改写等查询特征；分层只作解释，不用事后挑子集宣布总体胜出。
- H3：在固定查询下，检索器改进与结构化流程成功率是不同问题。原六次失败不能通过换检索器追溯改写为成功。

预期贡献是可复现的受控比较、错误分解与成本分析；这里没有提出新的检索算法，也没有已有 V2.0 效果结论。

## 2. 三种方法的可比较定义

| 方法 | 计划中的实现定义 | 研究价值 | 主要风险与控制 |
| --- | --- | --- | --- |
| BM25 | 原冻结 tokenizer、k1=1.5、b=0.75、相同候选文本和 document_id；作为固定对照，不额外扩大调参预算 | 明确词面匹配基线，便于定位实体/数字匹配 | 同义表达漏检、ASCII 分词限制；记录而不在主实验中悄悄改 tokenizer |
| Dense Retrieval | 一个预训练英文文本双编码器，query/document 各编码一次；先采用归一化向量余弦相似度与精确全库搜索 | 检验固定查询的语义表示是否改善关联检索 | 模型域偏移、精确实体/否定混淆、预训练污染；不微调，完整保存 checkpoint/revision、输入模板、pooling、截断及归一化 |
| Hybrid Retrieval | 同一 BM25 与同一 Dense 的排名做等权 Reciprocal Rank Fusion（RRF）；不混加不可比原始分数 | 检验互补，分析各路独有命中与融合损失 | 深度截断和排名稀释；开发阶段冻结深度与融合常数，无隐藏模型或额外 Prompt |

Dense 双编码器是已有检索路线，DPR 的证据来自开放域 QA，不是 Flickr8k 的性能保证。[Karpukhin 等，2020](https://aclanthology.org/2020.emnlp-main.550/) BEIR 的跨域比较支持保留有竞争力的 BM25 对照，不能把神经表示当作天然更优。[Thakur 等，2021](https://arxiv.org/abs/2104.08663)

RRF 计划得分为两路 `1/(c + rank)` 之和；rank 从 1 开始，未进入该路保留列表的文档该项记零，同分按 document_id 升序。融合常数 c=60，初始固定每路深度 L=100，最终返回 top10；这是可检验的协议选择，不是已验证的最优参数。c=60 参考原论文设置。[Cormack 等，2009](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf)

Dense checkpoint 尚未选定。后续最多核验两个候选的英文检索适用性、许可证、大小、CPU 可行性和训练来源透明度，仅在 tuning 队列选择一个；validation 只验收锁定版本，不继续挑模型。无法确认身份或获取许可时停止该候选，不静默替换。5,000 文档先精确搜索，不引入 ANN 的额外近似误差。索引必须绑定 corpus/model/编码配置哈希，禁止读到另一个 split 的缓存。

直接使用 CLIP 图像向量检索 caption 会改变输入表示和研究问题，留作独立扩展，不混进本轮三路文本检索主比较。重排器、Agent 动态规划和微调同样不属于 V2.0 首阶段。

## 3. 开发、验证与新确认数据

以下只是**拟议划分**，尚未生成 ID、文件或新 qrels。后续先核查所有历史使用记录，再以图片为单位固定清单与 SHA256。V1.1 原文件、冻结 Manifest、Prompt、图片、qrels、GPU 输出均保持原件。

| 队列 | 拟议来源 | 拟议查询图数 | 用途 |
| --- | --- | ---: | --- |
| 历史诊断 | V1.1 已用 dev20、test 诊断20及独立100 | 不新增 | 仅复放已保存查询，诊断接口和失败，不作为新确认样本 |
| V2 tuning | 原 dev 排除已用20后的980图中选择 | 100 | 选择最多两个 Dense 候选中的一个；错误分析和接口调试 |
| V2 validation | 与 tuning 按图不重叠的原 dev 剩余图 | 100 | 锁定后一次验证；不迭代选择参数；dev 另780图保留 |
| V2 final test | 原 test 排除已暴露前120后的880图中选择 | 200 | 方法、预算和指标冻结后一次确认；另680图保留 |

未来队列选择规则建议：将允许集合内每个 sample_id 按 `SHA256("vea-v20-split-v1:0:" + sample_id)` 升序排列，在 dev 依次取前100、后100；在允许 test 内取前200。不得按 caption 内容、像素特征或效果选图。历史额外暴露、重复/近重复审查若改变允许集合，应在看新结果前登记规则、原因、调整后数量和清单，不声称上述数量已经验证。

同一图片的五个 caption 始终在同一分组。拟沿用镜像原 train/dev/test 边界，检查图片哈希重叠和预定义的近重复规则；无法排除预训练暴露时明确保留限制。原 train 只可用于未来实现调试或资源评估，不做监督训练，若使用也须登记暴露。

候选库沿用每个原 split 的完整 caption 集：dev/test 各5,000条，不按查询图数缩成500/1,000条，不加人工难负例、不重标 qrels。tuning 和 validation 共享 dev 全库是明确的无监督索引设定；这不等于查询标注共享，不能把它写成全库级隔离。test 候选文本本就是公开语料，真正待保留的是新查询图及其结果不参与调参；这也不消除 Flickr8k 预训练污染。

在不查看 test 指标的情况下为最终候选库编码是允许的索引步骤，后续仍需授权和日志。test 标签、检索排名和定性错误不得进入模型、Prompt 或融合选择；若 validation 触发方法修改，它即成为已暴露开发数据，需另登记新验证队列，不能反复使用却仍称一次验收。test 失败或负结果也照常报告，不更换队列。

## 4. 受控实验与统计决策

主要实验矩阵只有一行查询来源、三列检索器：

| 查询来源 | BM25 | Dense | Hybrid |
| --- | --- | --- | --- |
| 固定 Baseline 图像描述 | 固定对照 | 次要方法比较 | **主要比较：Hybrid − BM25** |

每个新队列先按批准的固定 VLM 方法生成查询并保存；检索器不各自调用 VLM。一次生成失败使该图三个分支均记零；某检索分支失败使该分支及依赖它的融合分支计零，例如 Dense 编码或排名失败时 Hybrid 也失败。保留原异常，不以 BM25 回退冒充 Dense/Hybrid 成功。所有行保留 slot、sample_id、状态、attempt 和响应来源。未来查询生成也须明确 lifetime max_attempts=1 与终止条件，不能失败后替换结果。

若研究 format_details 查询，必须作为单独授权、冻结的次要2×3消融，不修补 V1.1 六条响应，不在 test 上选择更有利的查询来源。另报各查询来源的全部分母和共同成功子集，后者仅作诊断。

主指标为全图 **Hit@10**；次要指标为 Hit@1/5、MRR@10、CaptionRecall@10（五个同图 caption 命中比例）、生成/检索成功率和失败类型。可补充二元 qrels nDCG@10，但必须在最终冻结时确定定义，不能事后用它替代不利主指标。每个方法及配对差逐样本导出，失败计零。

统计计划：图片配对 percentile bootstrap，20,000次、seed=0、95%线性插值分位点；不将五个 caption 或三种检索器当额外独立样本。只对事先选定 Hybrid−BM25 作主要确认；其余比较为描述性分析。如需多个确认性假设，须提前登记多重比较策略。区间跨零表示不确定，不表示等效；显著性也不自动代表实际价值。

拟将 +0.03 Hit@10 作为开发者讨论用的最小实用改善目标，**不是观测效果、功效保证或已批准的成功阈值**。200图尚未做功效论证；最终确认前可仅用 dev 的配对不一致率评估精度并冻结规模，不能看 test 后追加样本至显著。报告区间宽度与成本，即使所有新方法均未改善也完成研究问题。

错误分层在 tuning 阶段预定义：实体/数字或可见文本、动作/关系、同义改写、泛化主题误配、查询生成遗漏、合约失败、检索执行失败。人工分析采用不知道方法名的混合结果展示，记录判断依据；不得修改现有同图关联 qrels 来迎合 Dense。原始 qrels 的负例假设与视觉正确性仍是局限。

成本分别记录语料编码次数、query 编码次数、索引构建 wall time、冷/热检索延迟 p50/p95、索引字节与内存；有 GPU 时才记录实际硬件显存。固定设备、线程、batch、候选规模及缓存规则，延迟测量随机/轮换方法顺序，启动与热态分开。保存 corpus/model/revision/软件/seed/参数/源码 Commit、运行日志和原始排名。不同 split 候选库的分数不跨库混合。

## 6. 与真实事实核验的边界

Flickr8k 回答“保存的图像描述能否找回同图 caption”，没有外部事实、支持/反驳判定或独立证据可靠性标签。上述任何 Hit/Recall/MRR 增加都只能支持关联检索层结论。

真实事实核验需要另设数据轨道：带可核查 claim 的输入、可追溯外部证据库、检索相关性 qrels、支持/反驳/证据不足标签、来源可靠性与时间规则；按事件、来源或时间控制泄漏，必要时按事件做统计聚类。VERITE 图文真假标签不能直接替代检索 qrels。要进一步评估最终 verifier，才适合报告 Accuracy/Macro-F1、证据充分性与引用对应关系。该轨道的数据许可、标注协议与系统实现均为另行规划，本阶段不执行。
