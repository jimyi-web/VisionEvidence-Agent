# T04-6 候选改进设计（待实施）

2026-10-18。本文件是研究方案，不是已实现功能或性能结论。本阶段不调用 GPU、不修改 Qwen3-VL 后端、不新增数据集、不调整查询与评测规则。T04 旧设计的 GPU 验收继续单独审批。

## 研究问题与数据隔离

研究问题：在明确输入来源和失败类型的前提下，能否提高证据召回，同时保留可见编号、状态、关系并减少词面干扰？所有收益是假设。

现有 t04_v1 的 10 例已经参与失败分析、人工审核和方案构思，只用于历史回归/合约测试。不得再当作未见测试集；在其上修复指定失败不构成泛化提升。S01/S08 与 D01/D02 的共享内容也表明按行随机划分不足以隔离主题泄漏。

实施前另行建立有来源/授权记录的独立 dev 和未参与优化的 test，按场景、主题、实体、模板、近重复证据及其改写/翻译分组隔离。同一图片、事件或跨语言改写不得跨 split。证据语料的划分或共享策略须事先固定并记录，不能利用测试 qrels 构造词典。若暂时仅有新合成数据，应明确仍只评估合成检索，不宣称真实 VLM 泛化。

先冻结标注规范（部分覆盖、额外属性、冲突证据、编号、近重复、无证据）并标记来源、审核方式与争议；再固定 split、语料、qrels、版本和哈希。词表、翻译词典、停用词、阈值、融合权重仅在 dev 选择。测试标签不提供给查询/调参过程，尽可能由人保管或独立执行测试；没有第二名标注者时如实记录。测试运行后发现问题可报告，但继续优化须使用新未见测试集。

## 候选条件与可检验假设

保留原 Baseline 和 Structured-v1 为固定对照。各候选先单因素比较，再对在 dev 选定的有限组合做预先声明的消融，禁止穷举到测试最好。实施前在配置中固定条件数量、参数搜索范围、选择指标和最大试验预算。

| 候选 | 机制与假设 | 风险与验证 |
| --- | --- | --- |
| 可追溯回退 | 结构观察合法但 objects+visible_text 为空时，显式使用同一输入已有的原始视觉描述 | 原描述必须有来源且运行时真实可得，不能用用户待核验声明或人工参考描述偷偷替代；报告触发率、来源与回退子集收益 |
| 关键字段保留 | 检查已有原始观察到查询的数字、编号、开闭状态及关系的保留；候选字段化权重/关系表达 | 无法凭空恢复 VLM 未输出内容；规则可能误绑数字和实体。保留原文、字段来源，人工审核对象—属性/关系对应 |
| 中文与跨语言 | 先比较 Unicode 中文字符/字符 n-gram 等 CPU 路径，再独立评估经过审查的分词或跨语言表示 | 中文可分词不等于中文查询能匹配英文语料；中文—中文、中文—英文、英文—中文分层评估。依赖/模型需单独确认 |
| 同义词 | 版本化外部通用词典或独立 dev 定义的有限扩展，记录原词→扩展词、来源、权重 | 不能仅加 automobile/car 这一测试特例；检查多义词误扩展、候选膨胀及负例，扩展预算有界 |
| 通用词与冲突 | 比较通用词过滤/字段权重；另设编号、状态冲突的可解释重排条件 | 停用词可能删除关系/否定；冲突词需绑定实体，不能见 open/closed 就统一扣分。在事实核验任务中反证也可能有用，须与当前“同场景”相关性区分 |

## 回退的约束接口

回退是新实验条件 `Structured+fallback`，不修改 Structured-v1 历史行为。仅在合法解析后的检索字段全空触发；纯中文被旧 tokenizer 清空应记录 `unsupported_language`，单独交给语言候选处理，不能混称提取空。解析失败、达到生成上限、后端异常默认保留失败；要改变必须另设条件。有效查询无命中不自动扩大检索或无限重试。

记录 original_query、effective_query、trigger、fallback_used、source_type、source_hash、原错误、query_sources、retriever_version、候选前后结果、调用数、时延。最多一次回退构造、一次最终检索，不新增 VLM 调用；源描述缺失或仍无可支持词项则失败计零。原始视觉描述不能在真实流程中凭空获得：如果实际部署没有该输入，回退候选不能与仅图像条件直接比较，必须报告额外输入条件和覆盖率。

数字/状态/关系保护也分两层：只能确认“已有观察→查询”的保留；“像素→观察”正确性需要另行真实图像与人工标注验收。本轮不做后者，也不借此改变 Qwen 后端。

## 评测与停止规则

- 主指标：同样非空 qrels 的端到端 Recall@5、MRR@5；辅指标 Recall@1/3，完整保留失败记零及每类失败数量。预先确定主选择规则，例如先 Recall@5、同值再 MRR@5；具体阈值在测试封存前填写，不能见到测试结果再选。
- 机制指标：查询构造率、回退率及有效回退覆盖、数字/状态/关系保留率（明确可审核分母）、每语言/同义类别结果、无命中率、候选数量、查询/检索/端到端时延、扩展次数。不以子集成功率替代总体结果。
- 缺证样本仍不进入 Recall/MRR，但单列候选返回情况；若要评估拒答/缺证识别，需另定义算法、标注和协议，不能把零命中直接当正确拒答。
- 所有方法共享同一语料、K 和 qrels；重排候选池大小/成本另行固定且公平披露。记录检索前后排名、得分、版本、随机种子、依赖和硬件。
- 若测试规模和抽样设计支持，按独立场景分组做配对不确定性估计；不把近重复文档当独立样本，不默认对小合成集做显著性宣称。
- dev 预算耗尽或满足事先验收条件后冻结代码、配置、词典和选择理由，再运行封存 test。测试失败同样报告；不回填 qrels、不删不利样本、不按 test 结果重新选择候选。

## 建议实施顺序与验收

1. 先完成数据与输入可用性设计、标签规范及冻结计划；由人确认重大接口/架构选择。
2. 第一项 CPU 实现建议是显式空提取诊断与可追溯回退，保留原策略，覆盖无源描述、中文、异常和失败计零测试；只有原描述确实可得时才评估回退。
3. 在独立 dev 分别验证字段保留、语言/同义词及词频干扰候选；选择有限组合并冻结。
4. 一次性执行未参与优化的测试，报告收益、退化、成本和限制。真实 VLM/GPU 验收另行申请；没有相关运行则不报告视觉能力提升。

本设计未选定新增数据集、下载模型或引入依赖，也未承诺任何候选优于原方法。
